# Direct chunked video evidence implementation plan

**Goal:** Browser uploads video chunks to Cloudinary without passing bytes through BE; completed, verified uploads can be attached to order disputes and staff can review buyer/seller evidence.
**Architecture:** Reuse Cloudinary SDK/config, CORS and private ReportEvidenceUpload. Persist owned upload sessions, generate fixed signed authenticated uploads, verify provider metadata, register completed assets as private evidence. Add append-only order-report responses for buyer supplements and seller packaging proof.
**Tech:** Java 21, Spring Boot, cloudinary-http5, JPA/PostgreSQL/Flyway, MapStruct, Lombok.
**Spec:** User request in this chat, existing BACKEND_CODING_STANDARDS.md and private-evidence contracts.

## Constraints and decisions
- Preserve existing image and inspection APIs, dispute 48h rule and financial workflow. No commit/push/deploy.
- POST /api/video/upload-signature and POST /api/video/complete require MEDIA_UPLOAD_SELF and authenticated owner. Public ID generated by server; no arbitrary signing oracle.
- API secret remains in BE. Signed preset must be configured; authenticated delivery, overwrite=false, bounded formats/bytes/duration. Signature is time-limited by Cloudinary; BE session expiration checked independently.
- Provider verification is authoritative; never fetch FE videoUrl or trust FE bytes/duration. Retry/ownership/concurrency must be safe.
- GET /api/video/{uploadId}/playback checks original evidence visibility and returns short-lived provider URL; no streaming bytes through BE.
- Seller responses apply only to order disputes OPEN/IN_REVIEW. Staff sees all responses; parties see their own submissions. Existing image privacy does not expand.
- Existing global configured CORS reused; no wildcard credentialed origins.

## Review focus
- Replay must not overwrite a completed video or attach somebody else's asset.
- Wrong resource type/public delivery/unsupported format must be rejected.
- Seller evidence must be viewable by authorized staff without making other reports public.
- Completion must not accept partial chunks or stale upload sessions.
- Response finalization and attachments serialize on the report lock; refunds remain unchanged.
