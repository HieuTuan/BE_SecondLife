# Main Flow 1 Implementation Plan

> Execution: implement inline with superpowers:executing-plans; approved scope is the design discussed in this chat.

**Goal:** Draft/chat without charge, separate auditable AI valuation with one Valuation Credit, and idempotent publish with one Listing Credit.

**Architecture:** Preserve `/api/v1/posts`. Lock seller then post for state-changing operations; balance debits and ledger entries share the same transaction. Successful valuations are append-only and uniquely keyed by post/request UUID; failed synchronous calls roll back their debit.

**Tech Stack:** Java 21, Spring Boot, Spring AI (existing Ollama/Gemini), JPA, PostgreSQL, Flyway, JUnit/Mockito/Testcontainers.

**Spec:** Agreed scope in chat and `docs/requirements/SecondLife_SRS_System_v3.0_FE_BE.md` (FE-06, BR-CRD), excluding re-up and additional media/evidence APIs.

## Constraints and review focus
- Preserve current uncommitted RBAC changes; preserve applied V19 checksum and use V20 for audit hardening.
- No legacy credit conversion; no inspection-fee payment with listing credits.
- Reject wrong owner, invalid/negative prices, stale states, AI malformed output and duplicate publish.
- Retry with the same request ID/input returns the same immutable estimate; changed input conflicts.
- Test credit concurrency and migration using an isolated PostgreSQL database, not the application database.
